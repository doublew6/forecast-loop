# v0.1 recovery drill

## Scope

2026-07-28 使用完全合成的临时状态完成 `v0.1.0` 发布前恢复演练。演练没有读取、复制或
修改真实 `data/` 内容；临时数据库、恢复目录、Compose project、volume 和网络均在验证后
清理。

## Checks completed

- 对合成的主数据库、checkpoint 和可变文件根执行 `recovery backup`；
- 对备份 bundle 执行 `recovery verify`，核验 manifest、权限、文件集合、大小、SHA-256、
  SQLite integrity、foreign keys、migration heads 和核心表行数；
- 将 bundle 恢复到新的空目录，复核 restore receipt，并确认不会覆盖现有目标；
- 从 Alembic revision `0009` 构造带 sentinel run 的数据库，升级到 `0010` 后确认 sentinel、
  migration head、核心表、integrity 和 foreign keys 保持正确；
- 使用一次性 Compose project 和临时 bind mount 完成 migrate、API health、Web health
  及 Web 安全响应头 smoke。

对应专项命令均通过：

```bash
uv run pytest -q backend/tests/test_schema_recovery.py
uv run python scripts/migration_smoke.py
python3 scripts/docker_smoke.py
```

本页只记录可复核的演练范围和结果，不保存临时 artifact hash、真实数据路径或本机身份
信息。后续 schema、备份格式、Compose 拓扑或恢复流程变化时，应执行新的合成演练并追加
新的审计记录，不原地改写本次结论。
